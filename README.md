# 经营数据管理系统

TCL KA 经营数据分析的数据库化管理系统：替代手工维护 Excel 底稿，存叶子、算合计、出报表。

## 启动

```powershell
# 确保 uv 在 PATH（新终端每次都要）
$env:Path = "C:\Users\yiming7.xu\.local\bin;$env:Path"
# 首次：安装依赖
uv sync
# 启动（或双击 启动系统.bat）
uv run uvicorn app.main:app --port 8000
# 浏览器打开 http://127.0.0.1:8000
```

## 数据流

```
各品类指标表数据库(明细长表) ─┐
主文件底稿(1).xlsx 源表(宽表) ─┼─→ 来源模板解析 → 试运行预览 → 入库(upsert)
规划2 的 25实际(同期专用表) ──┘
        ↓
   facts 事实表（只存叶子：产品×渠道×字段×数据类型×年月）
        ↓
   查询引擎（渠道树聚合 + 公式重算 + 复合期间）→ 报表模板 → Excel 导出
```

## 核心目录

- `app/schema.sql` — 数据库结构（事实表/渠道树/字段/口径/导入模板/报表模板）
- `app/seed.py` — 种子数据：字段表、口径、来源/报表模板；渠道树从底稿块标签自动发现
- `app/calc.py` — 计算引擎：公式求值、树聚合、复合期间（如 `1-7月实际+8-12月预测`）
- `app/importers.py` — 导入引擎：宽表/明细两种来源形态 + 聚合校验 + 试运行预览
- `app/reports.py` — 报表引擎：模板渲染 + Excel 导出（样式规格模式）
- `app/main.py` — FastAPI 接口
- `static/` — 网页界面（零构建：录入/导入/报表三个页签）
- `测试helpers.py` — 测试公共工具：临时库副本隔离（防清空生产数据）+ chk 断言
- `测试计算引擎.py` / `测试导入.py` / `测试报表.py` — 三个测试套件（操作临时库副本，生产库不受影响）
- `校验数据导入.py` — 独立数据校验（抽样/聚合/明细/报表全表 vs 源表）
- `迁移数据.py` — 一次导入全部来源（`--yes` 确认入库；空库自动播种）

## 关键设计决策（与用户确认）

1. **只存叶子**：渠道树上的合计/上级节点一律运行时计算，不做手工维护
2. **同期不存储**：`同期` 是虚类型（base=实际 + year_shift=-1），查询取去年同月实际
3. **字段分 raw/formula**：比率指标（ASP/毛利率）公式化，聚合时先汇总成分再算公式
4. **口径与字段分离**：达成率/同比等跨数据类型口径是 measures（公式：实际/BP、实际/同期-1）；ASP 块的达成率/同比是**单价差**（实际−BP、实际−同期，原表公式 L3−M3/P3 验证），用 ASP达成率/ASP同比 两个差值口径；缺口待用户定义后注册
5. **导入配置驱动**：来源模板（宽表/明细）存于库中，0 值视为无数据跳过；月份标签与位置不符报警，默认按位置导入（吸取"源表忘了改月份名"教训），位置错乱但标签为真的表（规划2 的 25实际/26实际(预测)/26年预算）用 `month_mode=label` 按标签导入。共 7 个来源模板：主文件 26年实际/26年预算/25实际 + 智屏明细 + 规划2 同期/预测/预算（主文件预算只到 7 月，8-12月 BP 真值在规划2）
6. **复合期间**：报表列期间支持 `1-7月实际+8-12月预测` 这类混合表达式；报表模板占位符 `{m}/{m+1}/{k}` 支持期间与标题随查询月动态（经营预测3：查询 6月 自动出 1-6月累计 + 6-12月预测组 + 7-12月 + 全年）
7. **报表行列模型**：经营预测3 与原表一致——行=实体×字段（5 实体 × 收入/毛利率/净利 3 行，A 列合并），列=期间组×5 口径（45 列）
